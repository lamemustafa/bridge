## P1
1. **`agent.rs:1336` — enforce the ledger-movement date window.** `VouchersV2` only sets SVFROMDATE/SVTODATE, which the protocol reference (§5) says do not restrict collection membership. Read movement vouchers through the literal-`<FILTERS>` profile the agent already renders for `vouchers`, and validate every returned date against the range before aggregation (`window_not_honoured` on any outlier), for both the pre-window and in-window reads. Test with an out-of-range row.
2. **`agent.rs:2518` — reject incomplete voucher ledger entries.** An `ALLLEDGERENTRIES.LIST` row missing LEDGERNAME, AMOUNT or ISDEEMEDPOSITIVE fails the whole parse with `agent_read_protocol_invalid`; never drop an entry or emit `not_observed`. Applies to `vouchers` and `changed_since`. Test each missing field.
3. **`agent_import.rs:806` — reject incomplete entries during import verification.** Same rule for the read-back parser: an incomplete entry fails the parse with `import_verification_export_invalid`. Test.
4. **`agent_import.rs:530` — reserve the narration marker namespace.** Reject user narration or reference containing `[BRIDGE:` (case-insensitive, after entity decoding) with `narration_reserved_marker`, so no later voucher can carry another batch's marker. Test.
5. **`agent.rs:2727` — reject undeclared tool arguments before dispatch.** Validate the argument object against the selected tool's declared properties (`additionalProperties: false`) before calling the tool and return `argument_unknown:<name>`; a misspelt scope field must not widen a read. Test `ledgre`.
6. **`agent.rs:2476` — preserve whitespace around voucher entity references.** Switch the voucher-row parser to `trim_text(false)` as the changed-master parser already is, ignoring whitespace-only text outside active fields. Test `Income &amp; Expense` through `vouchers` and `changed_since`.
7. **`agent.rs:2399` — stable identity on changed masters.** Fetch GUID as well as MASTERID for changed ledgers and groups and require at least one non-blank stable identifier (`change_row_identity_invalid`). Test.
8. **`packaging/mcpb/manifest.json:12` — one binary per advertised platform.** Decision: the staging script cannot cross-compile, so it must generate a host-specific manifest at staging time (only the host's `os`/`arch` entry, pointing at a per-target path such as `bin/<target-triple>/bridge_mcp[.exe]`) and refuse to stage if the manifest would advertise a platform with no binary. Keep the committed manifest as the template with all platforms and document the per-host assembly in `packaging/mcpb/README.md`. Test the verifier.
9. **`agent.rs:1225` — voucher entries absent from the ledger snapshot.** When an entry references a ledger not present in the movement map (created or renamed between the ledger export and the voucher read), do not skip it: fail closed with `ledger_snapshot_drifted` unless a ledger selector was supplied and the entry is for another ledger. Test.

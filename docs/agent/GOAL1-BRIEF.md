## What to build

A new binary `bridge-mcp` (put it in `src-tauri/src/bin/bridge_mcp.rs` using `bridge_lib`, or a new crate `src-tauri/crates/bridge-agent` if cleaner) that speaks the Model Context Protocol over stdio (JSON-RPC 2.0, newline-delimited; support `initialize` (protocolVersion "2025-06-18" and "2024-11-05"), `notifications/initialized`, `tools/list`, `tools/call`, `ping`). Prefer the `rmcp` crate (official Rust MCP SDK) with the `server` + `transport-io` features and `#[tool]` macros; if it fails to build within 20 minutes, hand-roll a minimal JSON-RPC loop with serde_json — correctness over elegance.

Configuration: env vars `BRIDGE_TALLY_HOST` (default `localhost`), `BRIDGE_TALLY_PORT` (default 9000), `BRIDGE_AGENT_DATA_DIR` (default: the app data dir Bridge already uses), `BRIDGE_AGENT_MAX_ROWS` (default 500), `BRIDGE_AGENT_MAX_BYTES` (default 200000). All reads go through the existing loopback-only transport (never bypass `bridge-tally-transport`).

Tools (names exact; every tool returns compact JSON text plus a short human summary; every response includes `company` (the verified identity: name, guid, company_number, books_from), `read_at`, `evidence` (request sha256, response sha256, bytes, complete|partial + reason code), and `truncated: true/false`):
1. `tally_status` — probe `/status` + the company extent profile; returns product, release, education mode, endpoint, list of loaded companies with identity tuples, and any refusal reason. Never throws on "Tally not running" — returns a typed error object.
2. `list_companies` — identity tuples for loaded companies; flags ambiguous/duplicate GUIDs the way `VerifiedCompanyIdentity` does.
3. `outstandings` — args: `company_guid` (required), `direction` ("receivable"|"payable"|"both"), `as_of` (YYYY-MM-DD, optional), `ageing_basis` ("bill_date"|"due_date"), `top` (default 25). Reuse the existing native Bills Receivable/Payable read and computation. Return totals, ageing buckets, top parties by exposure, unallocated count, and the Partial reason if the existing code would refuse.
4. `ledger_masters` — args: `company_guid`, `group` filter (optional), `fields` ("basic"|"compliance"; compliance adds GSTIN, PAN, MSME/Udyam, bank, IFSC, email, phone, state, pincode from the existing party-ledger-master fetch). Paged: `offset`, `limit` (≤ MAX_ROWS).
5. `ledger_movement` — args: `company_guid`, `from`, `to` (dates), optional `ledger` name filter: per-ledger opening, debit total, credit total, closing over the window computed from windowed vouchers (use `<FILTERS>` with literal dates exactly as the existing voucher read does; never rely on SVFROMDATE/SVTODATE for scoping). If the existing code has TBALOPENING/TBALCLOSING support, use it; otherwise compute from vouchers and say so in `evidence.method`.
6. `vouchers` — args: `company_guid`, `from`, `to`, optional `voucher_type`, optional `ledger`, `offset`, `limit`. Curated FETCH (date, voucher number, type, party/ledger names, amounts with sign, narration, GUID, ALTERID, MASTERID). Cap bytes; report `truncated`.
7. `changed_since` — args: `company_guid`, `alter_id` (integer high-water mark) → vouchers and masters with ALTERID greater than the mark (server-side AlterID filter is documented as working in `TALLY_PROTOCOL_REFERENCE.md` §10.1; if a profile for it does not exist yet, build it as a NEW xml profile file, not by editing sealed ones), plus the current company ALTVCHID/ALTMSTID.
8. `read_evidence` — returns the last N evidence records (request/response hashes, bytes, timing, complete/partial) for this session.
9. `egress_log` — returns the last N egress receipts (see below).

Egress receipt: every tool call appends one JSON line to `<data_dir>/agent-egress.jsonl` with `{ts, tool, args_sha256, company_guid, rows_returned, fields_returned:[...], bytes_returned, response_sha256, truncated, redaction_preset}`. Support `BRIDGE_AGENT_REDACTION` = `none|mask_parties|drop_narration` applied before returning (mask party names as first 2 chars + `…` + last 2; drop narration text). This file is the product's DPDP answer — make it append-only and never include voucher bodies.
